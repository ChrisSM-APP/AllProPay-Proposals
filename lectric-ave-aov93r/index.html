EPOS API -- How Integration Works

EPOS is built with developer-driven setups in mind. Ian's concern about rebuilding his workflows is the right one to raise -- it is exactly what happens when merchants move to platforms that do not expose a proper API. EPOS handles it differently.

  • REST API access. Payment initiation, status queries, voids, refunds, and transaction history are all accessible via API. No locked-in terminal dependency for developers.
  • Tokenization. Cards are tokenized at capture. Ian's fraud controls and workflow logic can reference tokens directly -- no need to handle raw card data in his own systems.
  • Webhooks and event hooks. Transaction events (authorized, declined, settled, refunded) fire webhooks to Ian's endpoints. His existing automation logic that responds to Elavon Converge events can be rerouted to the EPOS equivalents.
  • Fraud and risk controls via API. AVS, CVV, velocity controls, and custom risk rules are accessible through API parameters. The fraud controls Ian built can be replicated -- and in some areas extended -- through EPOS.
  • Sandbox environment. Full test environment available before any live traffic moves over. Ian can validate his existing workflows against EPOS responses before cutting over a single transaction.
The goal is a map, not a rebuild. Before anything switches, we walk through Ian's current Elavon Converge API calls and match them to the EPOS equivalent endpoints. Where it maps 1:1, nothing changes in his code. Where there is a difference, we flag it upfront so there are no surprises mid-migration. Most integrations like this resolve in hours, not weeks.
AllProPay Partner Program

Ian asked about partner incentives. AllProPay has an active partner program. Here is how it works:

  • Ongoing residuals. Partners earn a share of the processing revenue from every account they refer in, for as long as that merchant processes. This is not a one-time referral fee -- it compounds over time.
  • No minimums or quotas. One referral pays. Ten referrals pay more. There is no pressure to hit a number, and no program expiry if Ian goes a few months without a referral.
  • Direct support for every account. Ian has direct access to Jason. Any merchant Ian refers in gets the same direct line -- not a corporate hold queue.
  • Co-branded resources. If Ian wants to offer payment processing as part of his own service offering, AllProPay can provide co-branded materials, pricing collateral, and technical documentation to support that.
  • Non-exclusive. Ian does not need to stop working with other providers to participate. The program is open and has no exclusivity requirement.

The specific residual split and any volume-based incentives are walked through in a brief partner onboarding call. Jason can cover the full structure in under 15 minutes.
